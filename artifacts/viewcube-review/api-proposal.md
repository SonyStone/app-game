# Предложение интерфейса solid-view-cube

Статус: проект контракта для обсуждения и последующей реализации. Пакет уже существует как `@app-game/solid-view-cube`, но остаётся private workspace-пакетом. Solid в workspace закреплён на `2.0.0-rc.4`. Переход к framework agnostic реализации не требуется.

## Выбор контракта

Предлагаю controlled-компонент SolidJS 2, который получает фактическую ориентацию viewport и отдаёт запрос с уже вычисленной новой ориентацией. Он содержит геометрию куба, выбор целей, roll, соседние виды, drag и snap. Приложение содержит камеру, pivot, distance, projection, сохранённый Home и анимацию viewport.

| Вариант | Что приходится делать потребителю | Оценка |
| --- | --- | --- |
| Текущий `camera + onOrbit/onRoll/onSetView` | Повторять модель камеры и вычислять результат жестов | Слишком сильная зависимость от Grease Pencil |
| `orientation + onNavigate` | Перевести пару векторов в свою камеру и применить переход | Рекомендую; правила кнопок реализованы один раз |
| Передать целиком camera adapter с get/set/animate/orbit/roll | Реализовать большой контракт и управлять его реактивностью | Пока не оправдано |

Не добавлять заранее отдельный store/controller, плагины рендеринга или адаптеры для всех движков. Первый адаптер написать в Grease Pencil. Второй реальный потребитель покажет, что стоит выделить дополнительно.

## Минимальные публичные типы

```ts
import type { JSX } from 'solid-js'

/** Вектор в мировой системе координат потребителя; вход не мутируется. */
export type Vec3 = readonly [x: number, y: number, z: number]

/** Ориентация viewport без позиции, дистанции и типа проекции. */
export type ViewOrientation = {
  /** Единичный вектор от orbit target к камере. */
  direction: Vec3
  /** Единичный экранный up в мировых координатах, перпендикулярный direction. */
  up: Vec3
}

/** Локальные направления подписей куба в мировой системе. */
export type ViewReferenceFrame = {
  /** Нормаль Top; по умолчанию +Z. */
  up: Vec3
  /** Нормаль Front, направленная от объекта к камере; по умолчанию −Y. */
  front: Vec3
}

/** Запрос применения полной ориентации. В callback нет пиксельных delta и Euler-углов. */
export type ViewNavigation =
  | {
      source: 'preset' | 'adjacent' | 'roll' | 'snap'
      orientation: ViewOrientation
      transition: 'instant' | 'animated'
    }
  | {
      source: 'drag' | 'compass-drag'
      phase: 'start' | 'move' | 'end' | 'cancel'
      orientation: ViewOrientation
      transition: 'instant'
    }

/** SolidJS 2 props. Компонент читает изменения props реактивно. */
export type ViewCubeProps = {
  /** Реальная ориентация камеры в отображаемом кадре. */
  orientation: ViewOrientation
  /** Применяет или отклоняет запрос; возврат Promise не используется. */
  onNavigate: (request: ViewNavigation) => void
  /** Восстанавливает сохранённый Home приложения; без callback кнопка скрыта. */
  onHome?: () => void
  /** Направления подписей куба, независимо от экранного up камеры. */
  referenceFrame?: ViewReferenceFrame
  /** Разрешение анимации дискретных переходов; по умолчанию false. */
  animated?: boolean
  /** Показывать компас; по умолчанию true. */
  compass?: boolean
  /** Запрещает взаимодействие, сохраняя показ внешней ориентации. */
  disabled?: boolean
  /** Размер области виджета в CSS px; по умолчанию 160. */
  size?: number
  /** Стили контейнера; позиционирование задаёт потребитель. */
  class?: string
  style?: JSX.CSSProperties
}
```

Этот TS-фрагмент описывает проект интерфейса, он не компилировался как часть библиотеки. При реализации тип `JSX` следует импортировать из публичного entry point, принятого установленной сборкой SolidJS 2.

## Контракт поведения

- Правая система координат. `right = cross(front, up)` для reference frame; экранный `right = cross(screenUp, direction)` для камеры. Отдельно описать преобразование из left-handed движков в адаптере, если появится такой потребитель.
- `direction` всегда target→camera. Не использовать неоговорённое слово `forward`, которое легко принять за противоположное направление.
- Векторы finite, единичные и ортогональные с допуском. Нормализовать погрешности вычислений; нулевые, NaN и параллельные direction/up должны давать понятную ошибку валидации, а не вырождённую CSS-матрицу. Входные массивы не мутируются.
- Переход на грань возвращает и direction, и up. Один direction не определяет roll; на Top/Bottom нельзя восстанавливать ориентацию через случайный yaw=0.
- CW/CCW определяется вращением изображения на экране. Внутренние знаки quaternion/axis-angle не входят в API.
- Соседние стрелки используют экранные направления после roll. Для front/back/top/bottom нет независимых ручных схем размещения кнопок.
- `orientation` отражает фактический viewport, в том числе каждый кадр анимации и внешнее вращение мышью. Запрос `onNavigate` не означает, что камера уже изменилась.
- Для drag приложение синхронно применяет запрос в реактивное состояние. Компонент считает движение от стартовой ориентации жеста, чтобы не зависеть от частоты кадров и задержки props. `start` возникает после преодоления порога drag, без ложного click; `cancel` оставляет последнюю применённую ориентацию.
- Внешняя смена ориентации во время drag отменяет жест; собственные отражённые обновления drag не считаются внешней сменой. Это правило требует проверки интеграционным тестом.
- Анимация выполняется в одном месте, в контроллере viewport. Куб следует за камерой. При `prefers-reduced-motion` компонент запрашивает `instant`, даже если `animated=true`. Длительность/easing задаёт приложение; отдельный таймер для куба не нужен.
- Компонент не меняет pivot, distance, drawing mode и projection. Приложение решает, снимать ли привязку к плоскости после запроса. Именно здесь находится интеграция с 2D Grease Pencil.
- Home делегируется приложению, поскольку может включать target, distance и projection. Для начального API не нужен встроенный формат сериализации камеры.
- `referenceFrame` позволяет Z-up и Y-up проекты, а также переопределение Front. UCS, если потребуется, обновляет этот frame через приложение.

## Пример интеграции

```tsx
<ViewCube
  orientation={viewOrientation()}
  onNavigate={(request) => viewport.applyOrientation(request)}
  onHome={() => viewport.restoreHome()}
  referenceFrame={{ up: [0, 0, 1], front: [0, -1, 0] }}
  class="viewport-cube"
/>
```

`viewOrientation`, `applyOrientation` и `restoreHome` в примере обозначают будущий адаптер приложения. Они не существуют сейчас. На входе адаптера нужен полный базис direction/up; сведение обратно только к текущему `setViewDirection` потеряет roll. Наиболее прямое решение для viewport внутри адаптера: хранить полную ориентацию или корректно преобразовывать её в yaw/pitch/roll с обработкой полюсов.

Внутри библиотеки удобно использовать quaternion для вращений и интерполяции, не заставляя потребителя выбирать нашу математическую библиотеку. Публичный direction/up проще подключить к существующему `getCameraBasis` и не требует нового peer dependency.

## Организация реализации

```text
src/
  index.ts                 публичные реэкспорты
  ViewCube.tsx             Solid-компонент, controls и реактивность
  orientation.ts           публичные типы; операции вращения внутри пакета
  cubeGeometry.ts          единая геометрия граней, 26 целей и зон
  pointerGesture.ts        lifecycle pointer-жеста, cleanup
  ViewCube.module.css      внешний вид
```

Делить на большее число файлов до появления реальной сложности не нужно. Экспортировать локальные объявления в месте объявления, добавлять JSDoc с контрактами. Оставить одно публичное имя `ViewCube`; старое `NavigationCube` можно временно сохранить как deprecated alias для миграции. Не экспортировать `FaceDef`, CSS-матрицы, таблицы зон или drag-state.

Дополнительные параметры `snap`, `labels`, `inactiveOpacity`, ограничение world-up и события контекстного меню вводить только вместе с соответствующей работающей возможностью. Размер и цвета удобно менять CSS variables. `focalLength` заменить внутренним параметром CSS-перспективы: это не focal length камеры сцены.

## Подготовка самостоятельного пакета

Сейчас `private: true`, entry points ведут прямо в TS/TSX, peer dependency использует `catalog:`. Это нормально для workspace, но контракт потребления внешним проектом ещё не определён.

1. Зафиксировать и протестировать поддерживаемую версию SolidJS 2, пока это prerelease. Проверять разрешённый peer range в упакованном `package.json`, а не оставлять внешнему потребителю неразрешённый `catalog:`.
2. Выбрать и проверить формат поставки: ESM + declarations + CSS либо Solid source entry с явно документированным требованием компилятора. Для обычной установки предпочтительнее готовая сборка с external peer Solid runtime.
3. Объявить `exports`, `types`, `files` и CSS entry; сохранить импорт стилей при tree shaking через корректный `sideEffects`.
4. Подготовить README с соглашением осей, controlled lifecycle, примерами Z-up/Y-up, установкой стилей и отдельной интеграцией Grease Pencil.
5. Проверить tarball во внешнем минимальном SolidJS 2 приложении без monorepo aliases и TypeGPU. Учесть SSR: отсутствие доступа к window при импорте и корректный cleanup после unmount.
6. Публиковать только после исправлений и проверки API. Создание отчёта не означает публикацию пакета.
