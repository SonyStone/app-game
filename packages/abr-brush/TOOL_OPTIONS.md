# Tool options implementation

The active task is to expose and honor Photoshop preset tool options in ABR Viewer and Paint Studio, including the tool identity shown in preset thumbnails. Adding editor controls alone does not complete it.

## Current evidence

- Bundled examples contain 820 `PbTl` Brush, 9 `ErTl` Eraser, 4 `PcTl` Pencil, 26 `SmTl` Smudge, 79 `MixB` Mixer Brush and 1 `ShTl` Sharpen presets.
- `BrushFormValues.tool` and the Tool Options category read/write tool class, paint mode, opacity, flow, pressure overrides, pressure smoothing, legacy mode and tool-specific numeric/boolean settings. Unknown descriptor data and dormant settings survive edits. Native tool class IDs are strings, not blend-mode enumerations.
- Changes to shared dynamics also update their toolOptions copies, preventing stale settings on export.
- Viewer previews now receive preset flow/opacity. CPU/GPU previews implement paint blend modes through the shared blend function. Multiply, Screen and Hue pass browser pixel comparisons; the full preview verifier also passes its existing cases.
- Paint receives saved mode, flow and opacity through its existing preset adapter. `ErTl` selects Clear compositing. Native `ShTl` and `BlTl` filter existing canvas pixels with the preset's Strength and mode.
- Preset cards show the tool name. The embedded editor supports editing and switching Tool Options, import/application, mobile layout and main-thread/worker switching in isolated browser checks.
- Model checks: 223 Paint tests and 167 Viewer tests passed. Both typechecks and the Paint production build passed. All 939 bundled presets pass the metadata audit. These are not proof of native rendering parity.

- Optional saved RGB foreground/background controls now round-trip through ABR export and drive Viewer previews and Paint selection. Clearing a saved color removes its descriptor; unchanged fractional channels and unknown fields remain intact. Missing saved colors keep Paint's current foreground/background pair, initially blue-gray/white. Unknown color spaces are preserved by editing but explicitly rejected when applying in Paint.
- The color UI passes isolated browser checks for live preview updates, disabling local preview overrides, clearing/re-enabling saved colors, transfer to Paint, mobile layout and worker switching. Thumbnails use a non-white fallback preview color so Multiply no longer disappears solely because the default foreground was white.
- `verifyAbrEraser` applies a native ErTl preset to existing opaque tiles. At opacity 50%, it verifies premultiplied color/alpha, exact equality with eviction/disposable tails, and exact undo/redo snapshots. These checks pass on the actual GPU.

- SmTl now transports canvas pixels on the GPU in stamp order. Strength controls transfer amount; Finger Painting deposits foreground color at the start; Sample All Layers captures visible layers with their opacity/blend. Ordinary stroke-opacity/flow controls are hidden for Smudge and do not leak the host brush's values into it. Its mode picker exposes the seven native color-replacement modes.
- `canvasPickup.ts` provides borrowed, bounded GPU region textures for canvas-dependent tools. It sees active committed-input pixels, excludes disposable tails, handles negative coordinates and layer composition, and has no per-capture CPU readback. The tile cache may still need readback when evicting active tiles. Pickup defaults to at most 1024 pixels per side and 12 MiB of scratch; large brushes use filtered pickup.
- `verifyCanvasPickup` and `verifyAbrSmudge` pass on the GPU. They cover current/all-layer sampling, layer opacity/Multiply/visibility, seams, stale-empty regions, active ink/cancellation, Strength 100/20/0, Finger Painting, Dual Brush, event batching and one-tile-cache eviction. The embedded Viewer-to-Paint Smudge selection also passes main/worker and mobile checks.

- MixB now uses GPU reservoir/pickup wells. Wet and Mix vary per stamp, including their pressure/jitter controls; Load sets available paint; Flow controls deposition and depletion. Wet 0 uses reservoir paint regardless of Mix. Auto Clean and Auto Load apply after a successful stroke, and cancellation restores the pre-stroke wells. Existing well contents survive gestures and planned main/worker renderer replacement. The exchange/depletion constants remain approximations requiring native calibration. Eight 256² rgba16float textures add 4 MiB, included in renderer diagnostics. An explicit handoff temporarily adds one 1.5 MiB readback buffer; autosave does not read the wells.
- `verifyAbrMixer` passes real-GPU checks for Wet/Mix/Load/Flow, current/all-layer pickup, depleted/refilled/cleaned wells, cancellation, event batching and one-tile eviction. The shared sampler test covers independent Wet/Mix pressure and preview rollback. MixB ignores ordinary stroke-opacity settings; its Tool Options hide controls unavailable to this tool.
- The embedded editor imports the native Megapack Oil Pastel Soft MixB preset with Wet 39, Load 100, Mix 20 and applies edited Wet/Mix without an unsupported-engine error. `verifyMainThread` also paints MixB through both actual runtime endpoints in an isolated database, checks exact worker undo/redo document bytes and checkpoint restoration in both directions. The later tool-state checks below also cover the wells across renderer replacement. 223 Paint tests, 169 Viewer tests, both typechecks and the Paint production build passed.

## Native reference for Charcoal Champ 3

Read-only `currentToolOptions` inspection of the running Photoshop 26.0.0 on 2026-09-07 matched the bundled preset: Flow 75%, Opacity 100%, `prVr.bVTy = 2`, `opVr.bVTy = 0`, `szVr.bVTy = 3`, `textureDepthDynamics.bVTy = 3`, both toolbar pressure overrides false, Dual Brush Hard Mix. Pressure drives Flow; tilt drives diameter and texture depth. This confirms settings, not the pixel transfer model or live tablet response.

Viewer CPU/GPU previews previously applied Hard Mix to each tip before Flow, unlike Paint's accumulated-flow threshold. They now use the same order for Hard Mix and preserve raw opacity separately from soft-tip coverage. A regression distinguishes density changes from opacity changes. All 168 Viewer tests, both workspace typechecks and 19 browser GPU comparison cases plus device-loss handling passed. This corrects a Viewer/Paint discrepancy; it is not a claim that Charcoal now matches Photoshop.

The separate research task **Research Photoshop brush engine** has 107 validated native fixtures in `../../../photoshop-analysis/SAMPLED-BRUSHES.md`, plus settings and PNGs in that repository. Reuse those before changing renderer formulas. They establish canvas-aligned texture, separate secondary spacing and stochastic sampled-secondary orientation. The proposed 12× quantized Height model is validated only for opaque interiors; soft masks and pressure-varying depth remain unverified. The current renderer's fixed secondary orientation and approximate Height response remain native-parity gaps. The completed [parser audit](../abr-parser/docs/settings-audit.md) compared 20 ABR files, 1,071 presets and 129,716 typed values against Photoshop with zero decoding differences. It corrected wire-key documentation and records convenience-API limits; settings decoding alone does not establish rendering parity.

## Mixer commands and handoff

Manual Mixer Load Brush and Clean Brush are now available in Paint's color panel for MixB selections. They use the engine's registered, validated idle commands through the same ordered main/worker protocol. Clean before the first stroke sets preset identity and prevents begin from refilling it; Load refills foreground paint at the preset's Load value. Neither action changes document pixels/history or starts a save. Real GPU checks cover depletion/refill, clean/new-preset behavior; endpoint checks cover unchanged document bytes, active-stroke rejection, invalid commands and both execution modes. Load from canvas is also available from this panel and through Alt/Option-click. Load Solid Colors Only captures exactly one document pixel; multi-color loading samples a brush-sized square, normalized to the 256² well. Both honor Sample All Layers and preserve premultiplied alpha, including empty canvas. Auto Load refills from the captured template. The native tilted/asymmetric pickup footprint remains uncalibrated.

Validation: 230 Paint model tests and 34 UI tests passed, as did TypeScript and the production build. The Solid Primitives workers RPC is unsuitable here because it serializes self-contained functions into a separate worker, while these actions must share the existing renderer, resource scope and stroke queue in both execution modes.

A planned switch requests `checkpoint` with `includeTools: true`, finishes the current stroke, saves document pixels and captures reservoir/pickup/refill images as exact rgba16float bytes. The old renderer retires only after successful capture. `init.tools` validates and restores the payload before ready; Studio also waits for preset resources before enabling input. The payload lives only through the switch, separate from ABR exports and document autosave. Abrupt GPU loss and page reload do not preserve these transient wells.

## Stroke smoothing

ABR smoothing now uses a geometric leash for normal and Pulled String paths. Pulled String withholds paint until taut and ignores dormant Catch-up/Catch-up on Stroke End settings; the Viewer disables those controls without discarding their values. Adjust for Zoom scales the leash in both modes. Smoothing 0, the disabled preset toggle and Studio's None mode bypass all catch-up work.

For normal smoothing with Stroke Catch-up, an optional processor/session idle method advances the held stroke even when no new pointer event arrives. The runtime uses the installed Solid Primitives makeTimer with a single outstanding operation in its GPU queue. Each input packet resets that operation; finish, cancel, loss and disposal invalidate pending callbacks. Resource-session errors cancel the stroke and release its pins. Idle work does not start autosave or commit a partial stroke. Catch-up on Stroke End independently flushes the latest point when enabled.

The leash is currently 30 pixels times Smoothing/100, with optional zoom compensation; paused catch-up uses an exponential time constant of 20 + 120 × Smoothing/100 milliseconds. These constants are an implementation approximation, not native calibration. The behavioral reference is [Adobe stroke smoothing](https://helpx.adobe.com/photoshop/desktop/repair-retouch/clean-restore-images/create-smoother-more-polished-brush-strokes-with-stroke-smoothing.html). The separate pressureSmoothing and useLegacy tool flags still need implementation and measurement.

Validation: 247 Paint model tests, 35 UI tests, 171 Viewer tests, both typechecks and the production build pass. Actual main/worker GPU checks hold the contact without pointer events, verify catch-up reaches the pen, verify Pulled String/slack contact and None behavior, then compare exact undo pixels. The Viewer CPU/GPU suite passes 23 cases and device-loss handling. Unit checks cover elapsed-time partitioning, zoom compensation, preserved tablet axes, dormant settings, finish and idle failure cleanup.

## Eraser autosave and reopening

`eraserPersistenceVerification.ts` runs Brush/Pencil/Block through the production main-thread and Vite worker endpoints using isolated IndexedDB databases. The curved stroke crosses positive/negative tile coordinates in a nine-tile multicolor fixture. It checks partial-opacity Brush/Pencil coverage and fully clearing Block coverage, restores from a selected history source with Alt, closes/recreates the endpoint, and checks that a subsequent ordinary stroke erases again.

## Saved CMYK colors and ICC selection

Tool Options now accepts a local CMYK `.icc`/`.icm` file. The profile belongs to one editor session. The user must choose the source CMYK working profile used in Photoshop; no profile is guessed or redistributed. The existing sRGB Paint document model stays unchanged. LittleCMS transforms float CMYK percentages to RGB/8 with relative-colorimetric intent and black point compensation. The converter lives in Chroma, separate from Solid and brush logic. A lazy browser adapter loads its 255 kB WASM asset through Vite.

Both saved colors, card previews and interactive previews react to profile replacement. Form reads/writes share the converter, so changing Flow or another unrelated field does not replace the original CMYK descriptor. ABR export retains fractional channels and unknown fields. Explicit RGB edits replace the source color; clearing removes it. Before invoking an asynchronous host callback, the Viewer creates a detached brush snapshot with resolved RGB colors. Paint therefore does not retain a live ICC transform and its saved brush survives editor disposal or profile changes.

The editor owns and disposes transforms, ignores stale file loads and retains the previous profile if a replacement fails. Non-CMYK ICC files and malformed profiles report errors. The upload primitive was inspected: its picker creates preview object URLs and does not own the ICC transform lifetime. This control uses a visible native file input, with a separate single-purpose Solid owner for conversion state. Tests cover replacement, failure, concurrent loads, clear, disposal, file limits, descriptor preservation and detached host colors.

The pinned LittleCMS binding has a local patch to expose its WASM asset for Vite and release profile input buffers and failed metadata-query allocations. The application only requests RGB/8 output; the binding’s generic transform helper does not allocate wider output sample formats correctly and must not be used here for float/16-bit output.

`verifyCmykProfile.ts` checks the actual WASM implementation against 15 native CMYK fill samples, then validates malformed input and transform disposal/reopening. `fixtures/cmyk-profile-comparison.json` records profile hash, native values and output. ## Paint symmetry

Studio now has a separate Paint symmetry button for Vertical, Horizontal, Dual axis, Diagonal, Radial and Mandala. Radial accepts 2–12 segments; Mandala accepts 3–10 and creates a reflected pair per segment. Angle, document-space center, Center in view and guide visibility are editable. Guides follow camera projection and do not enter exported pixels. Settings belong to the drawing, not an ABR preset; old drawings default to Off.

A renderer decorator copies emitted stamps after stroke processing and brush dynamics. It transforms ABR centers, orientation and UV handedness, including secondary tips, while preserving sampled pressure and random values. Canvas-aligned textures retain document coordinates. All copies share the stroke's opacity, commit, cancellation and Undo. No new GPU resources or shader variants are required. Round paint and eraser, and ordinary ABR Brush/Pencil/Eraser are enabled. Physical tips, retouch tools and custom engines are not enabled by the current capability check.

Runtime commands validate guide settings and finish any active stroke before changing axes. Checkpoints, autosave and portable files retain the settings in both execution modes. The UI rejects changes during renderer replacement or suspended document commands, without showing unsubmitted settings. Empty numeric controls do not submit NaN.

Validation: 511 Paint model tests and 35 UI tests pass, with TypeScript and a production build. The GPU verifier checks six modes with an asymmetric mask, reflected round painting and erasing across signed tile boundaries, disposable tails, exact Undo/Redo and cache sizes of one and sixteen tiles. This is partial native symmetry support. Wavy, Circle, Spiral, Parallel Lines, arbitrary paths and direct guide dragging remain unimplemented.
